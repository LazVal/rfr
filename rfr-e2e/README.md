# UI tests

Requires JDK 25, MySQL, and running auth, API and frontend services.
Configuration priority: system property `rfr.<key>`, environment variable
`RFR_<KEY>` (dots become underscores), then a fallback constant in code.
Blank values are treated as absent.

| Key | System property | Environment | Fallback |
| --- | --- | --- | --- |
| `base.url` | `rfr.base.url` | `RFR_BASE_URL` | `http://localhost:3001` |
| `auth.url` | `rfr.auth.url` | `RFR_AUTH_URL` | `http://localhost:9001` |
| `auth.db.url` | `rfr.auth.db.url` | `RFR_AUTH_DB_URL` | `jdbc:mysql://localhost:3306/rangiffler-auth?serverTimezone=UTC` |
| `auth.db.username` | `rfr.auth.db.username` | `RFR_AUTH_DB_USERNAME` | Local MySQL user |
| `auth.db.password` | `rfr.auth.db.password` | `RFR_AUTH_DB_PASSWORD` | Local MySQL password |
| `api.db.url` | `rfr.api.db.url` | `RFR_API_DB_URL` | `jdbc:mysql://localhost:3306/rangiffler-api?serverTimezone=UTC` |
| `api.db.username` | `rfr.api.db.username` | `RFR_API_DB_USERNAME` | Local MySQL user |
| `api.db.password` | `rfr.api.db.password` | `RFR_API_DB_PASSWORD` | Local MySQL password |
| `browser.channel` | `rfr.browser.channel` | `RFR_BROWSER_CHANNEL` | Empty (Playwright Chromium) |

Gradle forwards `rfr.*` properties to the test JVM. For example:

```powershell
.\gradlew.bat '-Drfr.base.url=http://localhost:3001' '-Drfr.browser.channel=chrome' :rfr-e2e:test --tests io.student.rangiffler.test.RegistrationTest
```

The URL is configured in `config/TestConfig`; test usernames and passwords
are generated by `utils/RandomDataUtils`.

## Доступ к БД и SQL

`data/db/Databases` содержит `AUTH` и `API`: у каждой БД свой
`DriverManagerDataSource` и `DataSourceTransactionManager`.
Репозитории и проверки используют общие статические методы `Jdbs`:

- `jdbcClient(database)` возвращает `JdbcClient` для выбранной БД;
- `inTransaction(database, action)` выполняет действие в транзакции с откатом при ошибке;
- `isTransaction(database)` проверяет активную транзакцию этой БД в текущем потоке;
- `sql(name)` загружает и кеширует UTF-8 ресурс `sql/<name>.sql`.

Все SQL тестового модуля находятся в `src/test/resources/sql`: запросы auth,
API, общие запросы и подготовка тестовых данных в `fixtures`. Значения передаются
через именованные параметры `JdbcClient`, без подстановки в текст SQL.

```java
Jdbs.jdbcClient(Databases.API)
    .sql(Jdbs.sql("common/count-user-by-username"))
    .param("username", user.username())
    .query(Integer.class)
    .single();
```

Run registration and subsequent login verification from the repository root:

```powershell
.\gradlew.bat :rfr-e2e:test --tests io.student.rangiffler.test.RegistrationTest
```

The test uses Playwright Chromium in headless mode and an isolated browser
context. `@UsePlaywright(UiOptions.class)` manages the browser lifecycle and
injects `Page` into the test method. Each run registers a unique user through the UI and verifies the
username in the protected profile after login. The registered user and API
profile are removed through `UserFixture` in a `finally` block, including when
the scenario fails.

## Пользователь из БД auth

Аннотация параметра `@User` подключает `UserExtension` без отдельного
`@ExtendWith`. Extension создаёт уникального пользователя через Spring JDBC
и передаёт его как `TestUser`:

```java
@Test
void userCanSignIn(@User TestUser user, Page page) {
  new LandingPage(page).open()
      .openLogin()
      .fillLoginForm(user.username(), user.password())
      .signIn()
      .header()
      .openProfile()
      .shouldHaveUsername(user.username());
}
```

Для параметра `Page` класс теста должен иметь `@UsePlaywright(UiOptions.class)`.
Каждому параметру `@User TestUser` соответствует отдельный пользователь.
Записи пользователя и прав `read`/`write` создаются одной транзакцией;
пароль кодируется тем же `DelegatingPasswordEncoder`, что и в auth.
Миграции auth должны быть выполнены заранее. Настройки подключения находятся
в `TestConfig`; значения по умолчанию соответствуют локальной конфигурации auth.
`BeforeEachCallback` создаёт пользователей до запуска теста, `ParameterResolver`
передаёт готовые объекты в параметры метода теста, а `AfterEachCallback`
удаляет профиль из БД API, затем права и пользователя из БД auth после теста,
в том числе при падении. Подключения к обеим БД используют `DriverManagerDataSource`.
Созданием и очисткой управляет `fixture/UserFixture implements AutoCloseable`.
Extension хранит fixture для каждого параметра, возвращает его `user()`
и явно вызывает `close()` после теста. Сам fixture можно использовать отдельно:

```java
try (UserFixture fixture = UserFixture.create()) {
  TestUser user = fixture.user();
  // Работа с пользователем; close() очистит обе БД при выходе из блока.
}
```

Профиль API ищется по `username`, поскольку UUID в auth и API различаются.
Перед профилем удаляются его связи дружбы, фотографии, лайки, связи фотографий
с лайками и статистика. Если профиль не был создан, очистка API ничего не меняет.
Очистка каждой БД выполняется собственной транзакцией, общей транзакции между
БД нет. При ошибке очистки API extension всё равно пытается очистить auth
и остальных пользователей, затем сообщает обо всех ошибках.
Аннотация поддерживается на параметрах метода теста, не конструктора или методов
жизненного цикла. Миграции обеих БД должны быть выполнены до запуска теста.

`LoginTest` проверяет полный жизненный цикл: наличие пользователя и прав до
входа, успешную авторизацию через UI, появление профиля API и отсутствие записей
в обеих БД после очистки extension. Последняя проверка выполняется в `@AfterAll`,
поскольку обычный `@AfterEach` запускается раньше `AfterEachCallback` extension.

```powershell
.\gradlew.bat :rfr-e2e:test --tests io.student.rangiffler.test.LoginTest
```

To use an installed Chrome instead of downloading Playwright Chromium:

```powershell
$env:PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD = '1'
$env:RFR_BROWSER_CHANNEL = 'chrome'
.\gradlew.bat :rfr-e2e:test --tests io.student.rangiffler.test.RegistrationTest
```
