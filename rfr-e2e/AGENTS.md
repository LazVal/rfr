# Ограничения rfr-e2e

Запуск, установка браузеров, настройки и структура пакетов — в [README](README.md).

- Новые классы клади в существующие пакеты; Page Objects и компоненты создавай по навыку [create-playwright-po](../.agents/skills/create-playwright-po/SKILL.md).
- SQL и локаторы не размещай в `junit` и `test`; JUnit не добавляй в `data`. SQL принадлежит репозиториям и ресурсам, локаторы — Page Objects и компонентам.
- Без комментариев и Javadoc в коде `rfr-e2e` (Java, Gradle, SQL, properties): смысл передают имена и `@Step`.
- Вход в тестах только через UI; токены в localStorage не подставлять.
- Проход сценария через Playwright MCP — не запуск теста. Успех подтверждается JUnit-прогоном через Gradle.
- Проверка snackbar подтверждает уведомление. Для проверки сохранения требуется повторное чтение с сервера без клиентского кеша; фото и лайки сейчас моковые и не сохраняются.
- Тестовые данные создаются и удаляются фикстурами (`@User` → `UserExtension` → `UserFixture`), без широких `DELETE`/`TRUNCATE`.
