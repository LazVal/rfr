# Ограничения rfr-auth

Запуск, настройки и контракт регистрации — в [README](README.md).

- Регистрация создаёт учётную запись только в `rangiffler-auth`. API-профиль появляется отдельно при первом `Query.user`; UUID между схемами не совпадают.
- Для регистрации нужен CSRF-токен той же сессии: сначала `GET /register`.
- `GET /login` без сохранённого OAuth-запроса уводит на фронтенд. Вход начинается с `/oauth2/authorize` или кнопки Login на фронтенде.
- Ключ подписи RSA генерируется при каждом старте. После перезапуска все выданные токены невалидны.
- OAuth-авторизации и сессии хранятся в памяти и теряются при перезапуске.
- Refresh token публичному клиенту не выдаётся. Отзыв access token в auth не обеспечивает немедленного отказа API: API проверяет JWT локально до `exp`.
